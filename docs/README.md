## How these are captured

The media is generated by [`scripts/record-demo.mjs`](../../scripts/record-demo.mjs), which drives **headless Chromium via Playwright** and records real composited page frames. This is deliberately *not* an X11/`ffmpeg` screen grab of a headless session — such grabs frequently record before the page paints and yield a **black** video. Playwright's `recordVideo` captures the actual rendered frames, so the output is guaranteed to show the real UI.

```bash
bun run dev            # start API (:3001) + web (:3000)
bun run db:seed        # ensure listings exist
bun run demo:record    # capture video + screenshots into docs/demo/
bun run demo:video     # .raw/*.webm → demo.mp4
bun run demo:gif       # demo.mp4 → demo.gif
bun run demo:highlight # demo.mp4 → demo-highlight.gif
```

Intermediate raw captures land in `docs/demo/.raw/` and are git-ignored; the finished `*.gif` / `*.mp4` assets are committed.

> **Note:** the capture targets `http://localhost:3000` by default. Override with `WEB_URL=... bun run demo:record` (e.g. when the web app is served on another port). The booking step clears prior demo-guest reservations so the reservation reliably succeeds on each run.
